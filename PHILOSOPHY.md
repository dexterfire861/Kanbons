The application should be seamless and understandable by warehouse workers and non-technical people involved in the inventory and supply chain process for the company Kanbons, which is a supplier to manufacturers across the country

Do not overengineer and add in many parts and components to the pages, they should be simplified and abstracted well enough to be traced through and understood if needed to debug. An example is that there are multiple SQL files for each table in the database so that if there is any specific change or problem with a table, that respective file acts as a sort of truth.

The UI should be functional but also dynamic. Currently the company uses an Excel sheet with Visual Basic functions that do a lot of the processing, so porting that over to an AI-native system should be as functional as it was before, without any of the clutter.

It should be scalable with new workflows and such that will be connected to this database soon afterwards. For example, taking in customer orders through an OCR ingestion workflow and adding that to the respective tables will be a feature, among others in the future which will be incorporated as per business needs.

The system should also be modeled and typed properly so that everything follows a proper structure, by defining models as much as necessary and using OOP principles to ensure it is well made and efficient.
